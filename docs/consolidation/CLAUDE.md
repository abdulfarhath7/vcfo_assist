# CLAUDE.md — VCFO Assist consolidation and Suite wiring

**Read this file, then every file in this pack's `docs/` in numerical order. Ignore
every other context, briefing or phase document in this repository** — `docs/00` to
`docs/10` already in the repo describe the earlier build and are superseded by this
pack where they disagree.

## Where this repo is today

It holds **two extensions and two manifests**:

| | `extension/` | `src/` + root `manifest.json` |
|---|---|---|
| UI | popup | side panel, five views |
| Knows the real MCA portal | yes — 7 captured schemas, `lib/mapping.js`, `content/filler.js` | no — `.example` stubs only |
| Engine, guard, verify, Suite client | no | yes |
| Fills a SPICe+ form today | yes | no |

Neither is shippable. One knows the portal, the other has the architecture.

## What you are doing

Consolidating onto `src/`, moving the portal knowledge across, and wiring it to VCFO
Suite — so a lead clicks one button and everything that can be automatic is.

The popup build stays in the repo, disabled, as the reference for MCA field knowledge
until the panel build has provably filled a real form.

## Hard rules

1. **Do not delete `extension/`.** Move it to `legacy/` and disable its manifest. It
   is the authority on MCA field knowledge until the panel build is verified.
2. **Do not hand-convert `mapping.js` into CSS selectors.** Port its addressing
   scheme instead — see `docs/02-consolidation.md`. Rewriting 219 lines of proven
   portal knowledge by hand loses the parts nobody remembers to carry.
3. **Field maps and recipes are generated by a committed script**, not typed. Commit
   the script and its output.
4. **The human boundary does not move.** Login, captcha, OTP, payment, signing and
   submission stay with the lead. The guard has no override path and no `submit` op
   exists.
5. **Never store, send, prefill or log MCA credentials.** `mcaLogin.userId` arrives
   empty and stays empty.
6. **Profile fetch happens inside a Suite tab**, never from the extension origin. See
   `docs/04-suite-wiring.md`.
7. **No dependencies, no bundler.** Plain JS with JSDoc. `npm run check` must pass at
   every phase.
8. **No tests in this repo.** Verify by loading unpacked, using
   `docs/06-acceptance.md`.

## How to work

- Append to `TASKS.md` after each phase.
- Judgement calls go to `QUESTIONS.md` with your default and the alternative. Keep
  going.
